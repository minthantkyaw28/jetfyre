When to pull an engine

An AI agent rewrites one model file, a fixed referee replays held-out engines, and every pull decision is priced in cycles of engine life.

Every pull is a bet on time

Pull too early

Every cycle left on the wing was already paid for. An engine that comes off with life to spare goes to the shop sooner, and the airline buys again the life it had already bought.

Pull too late

The aircraft stops flying. One industry estimate puts a single day on the ground after an engine event at $50,000 to $150,000, rising past $600,000 beyond three days.1 Boeing has put the cost of a grounded aircraft as high as $150,000 an hour.2

Why the price moves

After the 2022 sanctions, more than 400 leased jets worth almost $10 billion stayed in Russia, cut off from Western parts.3 One independent count found over 800 technical faults that forced cancellations or emergency landings there from January to late November 2025, against just over 200 in the same months of 2024.4 Elsewhere, and for separate reasons, overhaul turnaround for new-generation engines has risen more than 150% in five years, mostly from faults in the new engines and shortages of parts.5 Before the war, Russia supplied about 65% of the titanium in Airbus aircraft.6 None of these figures is the price of an engine cycle, but each one moves it. So the evaluator does not fix that price. It treats the price of engine life as a dial the airline sets.

How the loop works

The loop follows the autoresearch pattern:7 an agent proposes one change, a fixed referee scores it, and only clear wins survive.

  1. The agent reads results.tsv and writes a one-line hypothesis.
  2. It edits model.py, the only file it may touch.
  3. evaluate.py trains on four folds and replays the fifth, five times over, within 60 seconds.
  4. Each pull costs the life thrown away. Each failure costs 500 cycles.
  5. The change is committed only if the mean cost falls and it wins four folds of five. Otherwise it is reverted.
  6. The result is logged, and the loop starts again.

The FD001 test set and all of FD003 are sealed.8 Nothing in the loop reads them. final.py opens them once, after the last turn.

The score is the airline’s bill

The referee walks each held-out engine forward one cycle at a time, the way an airline sees it. At the first cycle where the predicted life falls to the threshold T, the engine comes off the wing, and the bill is the life it still had. If that moment never comes, the engine fails, and the bill is the failure cost. The score is the mean bill per engine, so lower is better.

def replay_cost(pred, T, c_fail=C_FAIL, c_cycle=C_CYCLE):
    """Return (cost, failed, wasted cycles) for one track's predictions."""
    n = len(pred)
    for i, p in enumerate(pred):
        life_left = n - (i + 1)
        if p <= T and life_left > 0:
            return c_cycle * life_left, False, float(life_left)
    return c_fail, True, 0.0

A score is only worth something if it cannot be gamed. Four guards stand between the agent and an easy number.

RiskGuardHow it works
Memorising an engineSplit by engineEvery row of an engine sits in one fold, so the model is never scored on an engine it trained on.
Peeking at the futureThe truncation checkThe referee cuts each engine at a random cycle and predicts again. If any earlier prediction changes, the run fails as a future leak.
A lucky foldThe four-in-five ruleA change is kept only if the mean cost falls and it wins on at least four of the five folds.
Learning the benchmarkThe sealed testThe test sets stay closed until final.py runs once, at the end.

Against published work

On the sealed test sets the usual measures are RMSE and the NASA score, both taken at each engine’s last recorded cycle. Lower is better for both, and the NASA score punishes late predictions harder than early ones.9 Published results cap the target life at 125 or 130 cycles, so the comparison is approximate. Our FD003 numbers come from a model trained only on FD001, while published FD003 results train on FD003.

Three players, one referee

Each player searches against the same evaluate.py, the same folds and the same cost. What differs is what each one is allowed to change.

PlayerWhat it can changeWeak spotBest cost
Greedy agentAnything in model.py: features, target, learner, loss and TOne idea per turn, and it keeps only clear wins, so it can stall at a cliff edge[__]
OptunaFive numbers on raw features: learning rate, depth, iterations, life cap and TIt cannot invent a feature or change the loss[__]

Run it yourself

Download the NASA C-MAPSS files first.8 train_FD001.txt goes in data/; the FD001 test and RUL files and all of FD003 go in sealed/. Then run these in order from the repository root.

pip install numpy pandas scikit-learn optuna matplotlib
python prepare.py
python loop.py "baseline"
claude "Read program.md and follow it."
python optuna_control.py
python analysis.py
python make_figures.py
python final.py --baseline out/model_baseline.py --best model.py
python publish_site.py
